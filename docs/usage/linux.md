# Tracing on Linux with bpftrace

This walkthrough runs the `demo` example in one terminal and attaches
`bpftrace` to it from another. The commands are the ones the Linux attach
checks run (`spike/scripts/attach-linux-attr.sh`). The output below was
captured on Ubuntu 24.04 (Linux 6.8, x86-64) with bpftrace 0.20.2 and perf
6.8.12, using `spike/scripts/capture-docs-linux.sh`; process ids, addresses
and paths differ on each machine.

The `demo` example handles one made-up order per second and fires three
probes in the provider `demo`:

| Probe | Arguments | Defined by |
|---|---|---|
| `tick` | `n: u64` | `probes!` |
| `checkout__entry` | `id: u64`, `customer: &str`, `order` as `{:?}` text | `#[probe]` |
| `checkout__return` | `ret: u64`, the total in cents | `#[probe]` |

## Requirements

- bpftrace, run as root. The checks use bpftrace 0.20 on Linux 6.8.
- x86-64 or AArch64. Nobody has attached to an AArch64 build by hand yet;
  CI runs the attach checks there.
- For the generated script: `cargo install --path crates/cargo-anyprobe`
  from the repository root.

## Terminal 1: run the demo

```text
$ cargo build --release -p anyprobe --example demo
$ target/release/examples/demo
pid=5062 backend=linux-sdt
order 0: ana, Order { items: 1, express: false }, 1750 cents
order 1: bo, Order { items: 2, express: true }, 4000 cents
order 2: chen, Order { items: 3, express: false }, 4250 cents
order 3: ana, Order { items: 1, express: true }, 2750 cents
...
```

The first line gives the process id for the other terminal. An optional
argument sets the interval in milliseconds: `demo 200`.

## Terminal 2: list the probes

`cargo anyprobe list` reads the probes from the binary, without root and
without running it:

```text
$ cargo anyprobe list target/release/examples/demo
demo:checkout__entry(id: u64, customer: str, order: debug)
    entry of fn checkout in demo, crates/anyprobe/examples/demo.rs:30
demo:checkout__return(ret: u64)
    return of fn checkout in demo, crates/anyprobe/examples/demo.rs:30
demo:tick(n: u64)
    probes! in demo, crates/anyprobe/examples/demo.rs:20
3 probes in 1 provider
```

bpftrace lists the SDT notes in the file:

```text
$ sudo bpftrace -l "usdt:$PWD/target/release/examples/demo:*"
usdt:/home/jhoward/git/anyprobe/target/release/examples/demo:demo:checkout__entry
usdt:/home/jhoward/git/anyprobe/target/release/examples/demo:demo:checkout__return
usdt:/home/jhoward/git/anyprobe/target/release/examples/demo:demo:tick
```

## Terminal 2: attach a one-liner

bpftrace names a USDT probe by the binary's path, the provider and the probe.
The program text is in double quotes here so the shell fills in `$BIN`:

```text
$ BIN=$PWD/target/release/examples/demo
$ sudo bpftrace -p 5062 \
    -e "usdt:$BIN:demo:tick { printf(\"tick %d\n\", arg0); }
        usdt:$BIN:demo:checkout__entry {
          printf(\"checkout id=%d customer=%s order=%s\n\",
                 arg0, str(arg1, arg2), str(arg3, arg4));
        }
        usdt:$BIN:demo:checkout__return { printf(\"checkout returned %d\n\", arg0); }"
tick 2
checkout id=2 customer=chen order=Order { items: 3, express: false }
checkout returned 4250
tick 3
checkout id=3 customer=ana order=Order { items: 1, express: true }
checkout returned 2750
tick 4
checkout id=4 customer=bo order=Order { items: 2, express: false }
checkout returned 2500
^C
```

bpftrace first prints a line saying how many probes it attached (left out
above). Press Ctrl-C to detach. The kernel then removes the probes, and the
demo's probes go back to costing one enabled check each.

A `&str` and an encoded argument each take two argument slots, a pointer and
a length, so `customer` is `arg1` and `arg2`, and `order` is `arg3` and
`arg4`. `str(ptr, len)` copies the string out of the traced process.
bpftrace reads at most 64 bytes of a string unless `BPFTRACE_MAX_STRLEN` is
raised.

## Terminal 2: run a generated script

`cargo anyprobe bpftrace` writes a script with one clause per probe, each
argument decoded by its type, and the binary's absolute path filled in:

```text
$ cargo anyprobe bpftrace target/release/examples/demo > demo.bt
$ cat demo.bt
// Generated by cargo-anyprobe 0.1.0 for /home/jhoward/git/anyprobe/target/release/examples/demo
// Run: sudo bpftrace -p PID THIS_FILE
// bpftrace reads 64 bytes of a string by default (BPFTRACE_MAX_STRLEN).

usdt:/home/jhoward/git/anyprobe/target/release/examples/demo:demo:checkout__entry
{
	printf("demo:checkout__entry id=%lu customer=%s order=%s\n", arg0, str(arg1, arg2), str(arg3, arg4));
}

usdt:/home/jhoward/git/anyprobe/target/release/examples/demo:demo:checkout__return
{
	printf("demo:checkout__return ret=%lu\n", arg0);
}

usdt:/home/jhoward/git/anyprobe/target/release/examples/demo:demo:tick
{
	printf("demo:tick n=%lu\n", arg0);
}
$ sudo bpftrace -p 5062 demo.bt
demo:tick n=6
demo:checkout__entry id=6 customer=ana order=Order { items: 1, express: false }
demo:checkout__return ret=1750
demo:tick n=7
demo:checkout__entry id=7 customer=bo order=Order { items: 2, express: true }
demo:checkout__return ret=4000
demo:tick n=8
demo:checkout__entry id=8 customer=chen order=Order { items: 3, express: false }
demo:checkout__return ret=4250
^C
```

`--provider` and `--probe 'checkout__*'` narrow the script to some probes.
`cargo anyprobe bpftrace -p anyprobe --example demo --release` builds the
example first and reads the result.

## Starting the program under bpftrace

`-c` starts the program with the probes already enabled, so no firing is
missed. The program then runs as root.

```text
$ sudo bpftrace -c 'target/release/examples/demo 200' demo.bt
```

## perf

perf records the same probes as events. It needs Linux 4.20 or later and a
perf that passes the SDT semaphore to the kernel; an older perf lists the
probes and records nothing.

```text
$ sudo perf buildid-cache --add target/release/examples/demo
$ sudo perf probe -x target/release/examples/demo -a '%sdt_demo:tick' -a '%sdt_demo:checkout__return'
Added new events:
  sdt_demo:tick        (on %tick in /home/jhoward/git/anyprobe/target/release/examples/demo)
  sdt_demo:checkout__return (on %checkout__return in /home/jhoward/git/anyprobe/target/release/examples/demo)
...
$ sudo perf record -e 'sdt_demo:*' -p 5062 -- sleep 3
[ perf record: Woken up 1 times to write data ]
[ perf record: Captured and wrote 0.019 MB perf.data (6 samples) ]
$ sudo perf script
            demo    5062 [001]   251.232713:             sdt_demo:tick: (595a2aa1a08c) arg1=10
            demo    5062 [001]   251.232718: sdt_demo:checkout__return: (595a2aa1a2ee) arg1=3000
            demo    5062 [001]   252.232771:             sdt_demo:tick: (595a2aa1a08c) arg1=11
            demo    5062 [001]   252.232774: sdt_demo:checkout__return: (595a2aa1a2ee) arg1=5250
            demo    5062 [001]   253.232851:             sdt_demo:tick: (595a2aa1a08c) arg1=12
            demo    5062 [001]   253.232854: sdt_demo:checkout__return: (595a2aa1a2ee) arg1=1750
$ sudo perf probe -d 'sdt_demo:*'
Removed event: sdt_demo:checkout__return
Removed event: sdt_demo:tick
```

perf numbers arguments from `arg1`, where bpftrace starts at `arg0`. The
values match orders 10 to 12 in the demo's output.

perf reads integer arguments directly. It reads a string only up to a NUL,
which an encoded argument such as `order` has and a native `&str` such as
`customer` does not.

## When it does not work

- The probes attach but nothing prints: the enabled check reads the SDT
  semaphore, which the tracer raises. bpftrace does this for `-p` and `-c`.
  perf needs the versions above.
- SystemTap needs the binary linked differently. See
  [GAPS.md](../GAPS.md#systemtap).

## Measuring overhead

The `overhead` example times an unprobed function and two probed ones. Run
under bpftrace with every probe counted, 1,000,000 calls of each:

```text
$ cargo build --release -p anyprobe --example overhead
$ sudo bpftrace -c "$PWD/target/release/examples/overhead 1000000" \
    -e "usdt:$PWD/target/release/examples/overhead:overhead:* { @[probe] = count(); }"
Attaching 4 probes...
pid=5124 backend=linux-sdt calls=1000000
baseline        1.4 ns/call
native        889.5 ns/call
encoded      1111.2 ns/call

@[usdt:/home/jhoward/git/anyprobe/target/release/examples/overhead:overhead:native__entry]: 2000000
@[usdt:/home/jhoward/git/anyprobe/target/release/examples/overhead:overhead:encoded__return]: 2000000
@[usdt:/home/jhoward/git/anyprobe/target/release/examples/overhead:overhead:encoded__entry]: 2000000
@[usdt:/home/jhoward/git/anyprobe/target/release/examples/overhead:overhead:native__return]: 2000000
```

Each call fires an entry and a return probe, so a firing took about 0.4 to
0.6 µs. The counts are 2,000,000 because the example runs an untimed pass
before the timed one. With no tracer the same example printed 1.4, 2.6 and
2.0 ns. [PERFORMANCE.md](../PERFORMANCE.md) has the `printf` and
`perf record` runs and describes what the numbers mean.
